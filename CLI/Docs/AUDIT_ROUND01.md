## 修复内容

| 问题 | 本轮处理 |
| --- | --- |
| Windows 输入未闭合引号、无效世界路径会退出整个交互会话 | 在每次交互输入范围内处理可恢复异常；用户可继续输入 |

| 原位会话另存副本后，后续无路径 `:save` 被错误跳过 | 将“已有持久副本”和“仍需写回来源”分开记录；另存后仍可明确原位保存 |
| 等待输入时取消，随后输入的 `:save` 仍能写回 | 读入返回后、补充结构名输入后再检查取消，拒绝后续命令并保留未保存副本 |

## 验证重点

- 引号错误、无效路径不能结束交互循环或丢失当前已打开的工作副本。
- 导出的文件不能随工作副本清理而消失；被拒绝的保存不能清掉 dirty 状态。
- 原位连续保存后更新来源指纹，真实外部变更仍应拒绝写回。
- 批处理必须完整预检后才开始修改；输入目录和压缩包在另存为时保持不变。
- 清理历史文件后，构建脚本、测试入口、项目资源和许可仍完整可用。

SIGINT 场景在 Linux 上验证：取消后返回的下一条输入不再执行。不同终端的阻塞读取是否立即返回，以及 Windows 控制台 Ctrl-C 行为仍需目标平台验证。macOS 进程测试使用没有自定义 Commands/Command.txt 的测试账户；不会为了测试删除用户命令文件。
