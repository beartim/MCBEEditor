## 修订内容

1. 双端对象存储定位不再在旧 UniqueID 缺失或有歧义时退回坐标匹配，避免保存/删除误伤同名称、同位置、不同 UID 的实体。优先原索引的原始字节，其次唯一原始字节匹配，最后唯一 UID；无 UID 的实体只能按原始字节确认。方块实体坐标回退也要求唯一命中。
2. iOS 对象编辑成功后在目标区块重新绑定对象快照，核对来源、现代 actor 原始存储键及保存字节，更新 UID、位置、记录索引和标题，支持迁移/改 UID 后再次保存。保存已提交但无法唯一刷新时明确显示“已保存”，禁止旧快照继续编辑，要求返回列表重新打开，避免误报写入失败或用旧身份再次写入。
3. Windows NbtEditorWindow 把尚未应用到树的输入也纳入退出检查，关闭提供保存、放弃、取消。切换节点前应用合法输入；输入无效时回到原节点并保留输入。无变动的输入不再触发 dirty。
4. Windows 保存期间冻结编辑内容并拦截关闭，防止回调尚未完成时继续改值、重入保存或提前关闭后漏掉 DidSave 刷新。保存失败保留 dirty；保存退出通过 Dispatcher 延后关闭，避免同步完成回调在 Closing 事件内递归关闭。
5. iOS 共用退出保护增加模态导航栈的下拉拦截，避免 sheet 下拉绕过未保存提示。原模态状态先保存，保存/放弃退出时恢复。最终只读复核指出过“放弃后父列表仍被锁住”的风险，本轮已补恢复及源码断言。

## 目标平台验收清单

1. 双端运行完整核心测试；Windows 再运行 `--cli-regression`。iOS 修改现代/旧式实体 UID 和坐标，保存两次，再删除，检查 actorprefix 键及 digp 引用、相邻实体不变。
2. 打开对象 A 后，在另一操作中删除 A 并将对象 B 放到相同坐标；旧编辑器保存和删除必须拒绝，B 字节不变。重复 UID 场景应拒绝无法唯一定位的记录。
3. Windows 仅输入新值，不按“应用”：分别关闭并选择保存/放弃/取消；输入非法数字，保存必须失败且窗口保留输入。切换节点不得静默丢值。
4. Windows 用慢保存/失败回调验证：保存中不能编辑或关闭；失败仍可修正和重试；成功后关闭让列表与地图重新读取。
5. iOS 编辑后尝试侧滑返回及 sheet 下拉；用明确按钮取消/放弃/保存退出；放弃后父列表应恢复原关闭行为。
