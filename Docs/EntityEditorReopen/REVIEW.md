# 独立复核与修正

初稿由独立上下文复核，未发现 Critical/Minor，发现 1 项 Important：旧
连续实体记录删除或移动后，记录序号发生变化；若仍用扫描器 stableID
定位列表行，最后一个实体连续保存可能覆盖中间实体的列表条目，并让
“已查看”标记串行。数据库中的实际实体仍正确，问题发生在列表快照。

复核者用实际控制器与存储代码复现。随后在正式回归中补充地图/居民列表
分别删除或移动首根的四种场景，修复前实际触发 10 条断言失败。改为每个
列表行独立 UUID 后，连续保存、删除及独立查看状态全部通过；最后重新
运行完整 `Scripts/run_core_tests.sh`，退出码 0。

修正使用测试验证，未再启动第二轮独立复核。没有遗留的已知复核问题。

复核未覆盖真机 UIKit 导航/布局、原生 LevelDB 错误原子性与并发句柄；
这些平台边界没有运行条件。既有异步世界修改通知代码未修改，保留未保存
内容保护，未新增并发验证。Windows、命令、ID 和颜色数据保持原字节，
本轮没有重新运行 Windows 构建。验证结果不扩展为上述未执行平台的结论。
